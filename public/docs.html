Documentación de la API

API REST para que cada empresa envíe y reciba mensajes de Telegram con sus propios bots. Todas las respuestas son JSON.

Autenticación

El administrador registra la empresa y genera un token de acceso (formato tgk_…). Envíalo en el header Authorization de cada petición:

Authorization: Bearer tgk_3f9a1c...

El mismo token sirve para ingresar al panel web de la empresa. Si se regenera, el anterior deja de funcionar al instante.

Flujo multiempresa

  1. El administrador crea la empresa en /admin y obtiene su token.
  2. La empresa crea uno o más bots con @BotFather (cada bot es un "número" distinto) y registra sus tokens con POST /api/v1/bots o desde el panel.
  3. Los usuarios escriben al bot en Telegram → el mensaje llega a la bandeja del panel y, si está configurado, al webhook de la empresa.
  4. La empresa responde desde el panel o con POST /api/v1/messages/send.

Cada empresa solo ve y usa sus propios bots, chats y mensajes.

Bots

GET /api/v1/bots

Lista los bots de la empresa.

POST /api/v1/bots

Registra un bot nuevo. El token se valida contra Telegram y se guarda cifrado.

curl -X POST https://TU_DOMINIO/api/v1/bots \
  -H "Authorization: Bearer TU_TOKEN" -H "Content-Type: application/json" \
  -d '{"token": "123456789:AAH..."}'
{
  "id": 1, "company_id": 3, "telegram_bot_id": "123456789",
  "name": "Ventas Acme", "username": "acme_ventas_bot",
  "mode": "webhook", "status": "connected", "last_error": null,
  "created_at": "2026-10-12 21:50:00"
}

POST /api/v1/bots/:id/reconnect · DELETE /api/v1/bots/:id

Vuelve a conectar el bot con Telegram, o lo elimina junto con sus chats y mensajes.

Enviar mensajes

POST /api/v1/messages/send

CampoTipoDescripción
bot_idnumberBot que envía. Opcional si la empresa tiene un solo bot.
chat_idstringObligatorio. ID del chat de Telegram (o @canal).
typestringtext (por defecto), photo o document.
textstringTexto del mensaje o pie de foto/documento.
media_urlstringURL pública del archivo (para photo/document).
parse_modestringHTML, Markdown o MarkdownV2.
reply_to_message_idnumberResponde a un mensaje concreto.
 
curl -X POST https://TU_DOMINIO/api/v1/messages/send \
  -H "Authorization: Bearer TU_TOKEN" -H "Content-Type: application/json" \
  -d '{"bot_id": 1, "chat_id": "987654321", "text": "<b>Pedido #123</b> enviado ✅", "parse_mode": "HTML"}'
// 201 Created
{
  "id": 58, "bot_id": 1, "chat_id": "987654321", "direction": "out",
  "type": "text", "text": "<b>Pedido #123</b> enviado ✅",
  "telegram_message_id": 412, "status": "sent", "created_at": "2026-10-12 22:01:13"
}

Nota: Telegram solo permite escribir a usuarios que hayan iniciado conversación con el bot (/start).

Listar mensajes

GET /api/v1/messages

QueryDescripción
bot_idFiltra por bot.
chat_idFiltra por chat de Telegram.
directionin (recibidos) u out (enviados).
after_idSolo mensajes con id mayor (ideal para sondeo incremental).
before_idPaginación hacia atrás.
limit1–200 (por defecto 50).
 
curl "https://TU_DOMINIO/api/v1/messages?direction=in&after_id=50" -H "Authorization: Bearer TU_TOKEN"

Conversaciones

GET /api/v1/chats

Lista las conversaciones (contactos) ordenadas por actividad. Filtros: bot_id, q.

POST /api/v1/chats/:id/read

Marca la conversación como leída.

GET /api/v1/me

Datos de la empresa autenticada y estadísticas.

Webhook entrante

Configura una URL con PUT /api/v1/settings ({"webhook_url": "https://..."}) o desde el panel. Por cada mensaje recibido enviamos:

POST https://tu-sistema.com/telegram/webhook
X-Signature: 5d41402abc4b2a76b9719d911017c592...   (HMAC-SHA256 del body con tu webhook_secret)

{
  "event": "message.received",
  "message": { "id": 59, "bot_id": 1, "chat_id": "987654321", "direction": "in",
               "type": "text", "text": "Hola, ¿tienen stock?", "sender_name": "Ana Pérez", ... },
  "chat":    { "id": 7, "chat_id": "987654321", "title": "Ana Pérez", "username": "anaperez", ... },
  "bot":     { "id": 1, "name": "Ventas Acme", "username": "acme_ventas_bot", ... }
}

Verificar la firma

// Node.js
const sig = crypto.createHmac('sha256', WEBHOOK_SECRET).update(rawBody).digest('hex');
if (sig !== req.headers['x-signature']) return res.status(401).end();

// PHP
$sig = hash_hmac('sha256', file_get_contents('php://input'), $WEBHOOK_SECRET);
if (!hash_equals($sig, $_SERVER['HTTP_X_SIGNATURE'] ?? '')) { http_response_code(401); exit; }

Errores

Los errores devuelven un código HTTP apropiado y {"error": "mensaje"}.

401Token inválido o ausente.
403Empresa desactivada por el administrador.
404Recurso no encontrado (o pertenece a otra empresa).
409El bot ya está registrado.
422Datos inválidos.
400 / 502Telegram rechazó la operación (el detalle viene en error).
